How to read the table next to GitHub’s usage report.

  1. Wall is observed completed_at − started_at, summed across the week’s runs of that job.
  2. Rounded min follow GitHub billing: each started job rounds up to the next whole minute (a 12-second lint is 1), then those minutes are summed. This is not ceil(combined wall).
  3. SKU is the usage-report runner SKU inferred from job labels / runner name.
  4. Est. $ (list) = rounded minutes × the documented per-minute rate for that SKU. Labeled as an estimate, not an invoice.
  5. Included-min burn is plan-minute consumption for standard hosted runners only (Linux 1, Windows 2, macOS 10 per rounded minute). Larger runners contribute 0.

Same rules as the free Action Job Summary. See the per-run demo for a single workflow. Public repos and typical self-hosted runners are often not billed the same way.

What to change

A concrete list so this week does not repeat.

Each item names the file or trigger to edit. Dollar and included-minute figures are this week’s waste that the change stops — at the same list prices.

  1. Collapse the Windows matrix to windows-2022 only

    In pinemark/studio/.github/workflows/desktop.yml, delete the windows-2019 and windows-latest entries from the test matrix. Keep one Windows image. Stops $14.2800 list and 2,856 included min this week.

  2. Move lint off macOS

    Run Desktop CI lint on ubuntu-latest (or ubuntu-slim). A 20-second job on actions_macos still burns 1 rounded minute × $0.0620 and 10 included minutes. On Linux it is $0.0060 and 1 included minute. Stops $4.7040 list and 756 included min if the 84 runs stay (84 × $0.0560 and 9 included min each).

  3. Stop running macOS e2e on every pull request

    Gate e2e to main, workflow_dispatch, and a nightly schedule — or require a run-e2e label. Do not pay 10× included minutes for a 6-minute UI suite on docs and API-only PRs. Leaving 12 of 84 runs (nightly + labeled) would have been $31.2480 and 5,040 included min less.

  4. Notarize on tags only — drop macos-latest-large from PRs

    Remove the notarize job from pull_request. Keep it on release / version tags. Larger runners cannot use included minutes; the 42 PR notarizations were $29.1060 list and 0 included min — pure overage at $0.0770/min.

  5. Delete the Windows job from API CI

    In pinemark/api/.github/workflows/ci.yml, drop test on windows-latest. The API ships Linux containers only. Stops $3.1000 list and 620 included min.

  6. Path-filter the 12-second Linux lint

    Add paths-ignore for docs, markdown, and studio/ so API lint does not start a billed minute on unrelated PRs. Combine lint into the test job if it stays under a minute. Small dollars; it is how 62 one-minute charges appear for 12 seconds of work.

  7. Skip Nightly desktop when studio/ did not change

    Add a paths filter or a “skip if no new commits in studio/” condition. Four of this week’s seven nightlies rebuilt macOS with no desktop diff. That pattern is $8.1840 and 1,320 included min on those four nights alone (4 × 33 rounded min × $0.0620 × 10 included).

  8. Move Nightly load off windows_8_core

    The load test fits on standard windows-latest (actions_windows at $0.0100/min). The 8-core SKU is $0.0420/min and cannot burn included minutes. Same 147 rounded minutes would be $1.4700 instead of $6.1740. Stops $4.7040 list.

  9. Stop auto-retrying the whole Release workflow

    The flaky notarize step re-ran package-macos and package-windows three times. Turn off workflow-level retry; retry the one failing step or fix the flake. Stops $4.7880 list and 792 included min of duplicate packaging.

  10. Pin Actionscope on a last step

    Add uses: Sofa-Loaf/actionscope@v0.1.3 as the last step on Desktop CI, API CI, Nightly, and Release so the next week’s Job Summaries use these same columns. Optional comment-on-pr: true if you want a screenshot-forwardable comment. No Stripe URLs in the Action — checkout stays on 28to3.me.
